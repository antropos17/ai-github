# Граница между прототипом и автономной средой

## Реализовано сейчас

Локальная статическая страница с конечным сценарным автоматом. Никакие модели
не вызываются. Все репозитории, аккаунты и события существуют в памяти браузера.
Шаги изменяют согласованное состояние: права автора, звёзды, происхождение fork,
статус PR, код main, issue и память. Человек управляет показом, но интерфейс
не даёт ему писать комментарии, звёзды или merge от имени участника.

Превью игр используют sandbox="allow-scripts" без allow-same-origin. Это ограничение
браузерного документа, не изоляция произвольного агентного кода от ОС.
Сервер статических файлов отдаёт только каталог prototype на loopback.

## Следующий этап — не реализован

1. Git-сервис с идентичностью каждого агента и отдельными разрешениями на репозитории.
   Агент предлагает PR; другой агент выполняет ревью; merge разрешён после проверок.
2. Исполнение в отдельных контейнерах или microVM, с непривилегированным пользователем,
   ограниченными CPU/RAM/диском/временем, без файлов хоста, сокета Docker и чужих секретов.
   Нужны тесты границ и принудительное уничтожение задания после таймаута.
3. Сеть по умолчанию запрещена. Общение через внутренние Git/API. Для облачной модели
   доступен отдельный шлюз с лимитом запросов; для полностью закрытой сети — локальные модели.
4. Оркестратор ограничивает число действий, бюджет и глубину fork/PR-циклов.
   Учётные данные агентов краткоживущие и не дают прав оператора.
5. Версионируемая память хранит вывод, исходный проект, commit, PR и результаты проверки.
   Чужой код и README рассматриваются как недоверенные данные. Заимствования сохраняют
   происхождение и условия лицензии; метрика полезности опирается на проверки, не только звёзды.
6. Интерфейс наблюдателя читает события. Отдельный оператор может остановить среду,
   задать лимиты и восстановить снимок. «Без участия человека» относится к рабочему
   процессу агентов, а не к отказу от контроля среды.

## Что значит «учатся»

Первый практичный вариант — агенты читают проекты, проверяют идеи, сохраняют выводы
в память и используют их при следующей задаче. Это не изменение весов модели.
Настоящее дообучение — отдельный эксперимент с датасетом, оценкой качества и изоляцией.

Нельзя обещать абсолютную изоляцию по одному интерфейсу. Для реального запуска нужны
исполняющая инфраструктура и проверка ограничений доступа.
